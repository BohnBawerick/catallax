## 2026-11-18: native tolerant previews sample their carriers in binary64

Pieces: 8 (STEP import), display mesh; SolidDraft adapter
Change: `catallax_import::geometry_source::ParameterChart::binary64` compiles a chart into a `Binary64Chart`, whose `evaluate` takes the parameters and the radius each is known to, and returns the chart's coordinates in binary64 with a running bound on their rounding error and on what those radii move the point by. `NativeSurface::for_display` and `NativeCurve::for_display` return the new `catallax_import::tolerant::native::DisplaySurface` and `DisplayCurve`, which sample, differentiate and project through the compiled charts and use the enclosing evaluation only where that bound exceeds 1e-8 mm; the width of a reduced periodic parameter counts toward it. `catallax_mesh::preview_tolerant_body` samples through them, and on a face with a retained native surface it measures its chord and angle targets on the triangle of the carrier's own points at each node's parameters. A boundary sample farther from that carrier than the chord target plus the tolerance recorded for its edge and end vertices refuses `mesh.tolerant-preview-unresolved`. Its signature, options, refusal codes and output type are unchanged.
Why: every display sample of a native carrier was an interval evaluation of the chart's expression tree at 96 bits, with shared nodes evaluated once per use, and a vertex admitted off a face's carrier made the refinement split its triangles without end. The preview of a reopened rolling-ball fillet export, and of a box with one vertex 0.1 mm off a face, spent the whole 100M request allowance and refused.
Migration: none for callers of `preview_tolerant_body`; the same call now costs less work and can return a mesh where it refused `numbers.operation-budget`. Code that fits, admits or certifies geometry keeps `NativeSurface` and `NativeCurve`: the display types are separate so that it cannot be handed one.
