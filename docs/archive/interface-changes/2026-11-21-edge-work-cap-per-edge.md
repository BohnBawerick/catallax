## 2026-11-21: the edge-gap checker's work cap is one allowance for an edge

Pieces: 3 (numerical admission), and the import piece's tolerant reader
Change: the 1,000,000 units of `numerical::gap::EDGE_WORK` are one allowance for a topological edge, shared by its uses on all its faces. Every numerical admission keeps one allowance per edge, and an edge whose uses together need more refuses with `numerical.gap-work-cap`, the same code as before. `numerical::read_import_use` keeps its signature; its `limits` is now what the use's edge has left, and the caller takes the returned `work` off the edge before the edge's next use. `numerical::read_import_use_counted` is the same with a count the work is added to whether the rule finishes or is refused, for a reader that goes on after a refusal. `numerical::gap::refit::refit`, the refit without a limit, is removed; `refit_within` is the one entry.
Why: Checkpoint 2 decisions, section 4.2 step 8: "A hard per-edge work cap refuses by name." 3.0A gave each edge use an allowance of its own, and the reviewer held roadmap item 3.0B's first one-model part on it. See [the milestone note](../milestones/3.0B-one-model.md#the-work-cap-of-the-edge-gap-checker-is-one-allowance-for-an-edge).
Migration: a caller that reads several uses of one edge keeps a count per edge, passes `EDGE_WORK` less that count as `limits`, and adds each use's work to it. One that goes on after a use it could not read calls `read_import_use_counted` and adds the count on both outcomes. A caller of `gap::refit::refit` calls `refit_within` with what the edge has left. An edge that newly refuses `numerical.gap-work-cap` needed more than one allowance for all its uses together.
