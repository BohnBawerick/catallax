## 2026-11-21: curvature-continuous fillet recipe operation

Pieces: recipe, features, application, field
Change: `catallax_recipe::Operation` gains `FilletG2 { body, edges, radius, fullness }`, written `"op": "fillet_g2"` and accepted only in `catallax-recipe/5` ([RECIPE.md section 4.5.3](../../RECIPE.md#453-curvature-continuous-fillets)). The radius must be positive and the optional fullness in (0, 5/4]; other values are recipe errors. The exact evaluators and `evaluate_incremental_outcome` build it on straight convex edges between planes of a convex polyhedral shell; the blend face is a `SplineSupport::RationalPatch` named `blend.edge`, as a fillet's is. New refusal code: `fillet.unsupported-g2-contact`; it also uses `fillet.unsupported-end`, `fillet.unsupported-corner` and `fillet.unsupported-overflow`. The variable-radius constructor's convex-shell refusals now read "planar band fillets need ..." instead of naming variable fillets; their codes are unchanged.
Why: roadmap 3.4, tools only SMLib has: a first build of curvature-continuous blends, after SMLib's blend-curve cross section (`SmBlendCurveCrossSectionFSG`, continuity 2).
Migration: `Operation` is `#[non_exhaustive]`, so callers that match it already have a fallback arm. The field kernel refuses `fillet_g2` with `field.unsupported-operation`, and the two-kernel comparison reports it as not comparable. SolidDraft has no command for it yet.
