## 2026-10-26: exact ordered face-loop application queries

Pieces: app, 2, 3, 4, recipe
Change: new `catallax_app::loops` module with `face_loops` and the `ApplicationBody::face_loops` and `IncrementalApplicationBody::face_loops` adapters. `FaceLoops` returns the face's surface handle, face sense, complete origin set and its stored loops in stored order. A `FaceLoop::Coedges` lists each coedge in stored cycle order with its travel sense relative to the edge, its travel start and end vertices (`None` for a ring edge) and the existing exact `EdgeCurve`; `FaceLoop::Vertex` carries the exact point and vertex name. A whole closed face has zero loops. New refusal `app.loop-face` for a face outside the selected result; edge-query refusals propagate unchanged and unsupported carriers stay `CurveSpan::Unsupported` per edge.
Why: drawing and section consumers should walk the actual boundary cycles instead of sorting display points or assuming the first loop is outer.
Migration: additive, see [exact trimmed application edge queries](0170-2026-10-25-exact-trimmed-application-edge-queries.md). Read `loops` in order, apply each coedge `sense` to the edge's stored direction, and do not infer outer or inner from position. Handles stay bound to the queried model; persist origin names. This adds no visibility, healing or persistent-handle promise, and loop order is not stable across unrelated rebuilds.
