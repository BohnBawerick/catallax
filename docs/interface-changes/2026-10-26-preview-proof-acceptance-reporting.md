## 2026-10-26: preview wait and proof completion reported separately; comparison on request

Pieces: verification driver, development head-to-head example and display benchmark, release evidence
Change: `control-catallax.py parts` adds `--compare`. Without it the report runs the `recipe` and `field` columns (and `print` when asked), omits `compare` rows, records `columns` and `comparison: {requested, status}`, and sets `comparison_disagreements` to `null`, meaning not requested rather than zero. With it the output is the previous three-column scoreboard. Each row gains `acceptance.recipe` and `acceptance.field`: a `preview` record that is `not-measured` unless the response carries a preview labelled `unproved` with a delivered display and its wait, and a `proof` record (the whole response wait against the 2000 ms background target, completed only when the response answered without refusal). `built` is true only when proof completed within its target, never from a preview. `run` and `report` summaries add `acceptance` counts with the same rules; existing `slow` lists and per-class targets are unchanged. `head_to_head.rs` adds a timed `preview` phase (`catallax_app::preview_body`, labelled `unproved`, own allowance) and a per-variant `acceptance` object with preview wait (build plus preview), proof wait (build plus certified display, measurement and STEP) and `built`. `head_to_head.py` summary rows add `preview_*`, `proof_*` and `built_after_proof` fields. `benches/display.rs` rows add `preview_ms`, `preview_wait_ms`, `preview_state` and `preview_target_ms`; `requested_wait_ms` keeps its certified-display meaning and excludes the preview time.
Why: [ARCHITECTURE.md](../ARCHITECTURE.md) separates the preview budget from background proof, and makes the second-kernel comparison an on-demand verification column.
Migration: `catallax-parts/1` keeps its format; readers must tolerate a missing `compare` key and a null `comparison_disagreements`. `.github/workflows/release-evidence.yml` now passes `--compare` because `tools/release/release.py` still requires the compare rows. `.github/workflows/parts.yml` is not edited here. To keep its current full scoreboard add `--compare` to its `control-catallax.py parts` command; to adopt the new decision leave it off, run comparison in a separate on-demand verification job, and read `acceptance` for preview and proof. `catallax-verify` has no preview request, so the driver reports preview as `not-measured` until a response carries a preview record; use the head-to-head example for measured preview waits. Historical scoreboards and the 1M, 20M and 100M allowances are unchanged.
