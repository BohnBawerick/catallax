## 2026-10-27: STEP import `propose` and `apply`

Pieces: `catallax-import`, application adapter (SolidDraft)
Change: Adds `propose(source, &ImportOptions) -> Result<ProposalSet, ImportRefusal>` and `apply(model, source, name, &ImportOptions, &[Decision], step) -> Result<Imported, ImportRefusal>`. This corrects the call sequence in [the wire types note](2026-10-27-step-import-repair-wire-types.md): `apply` takes the caller's `Model`, the options used for `propose`, and an optional `StepId` for face origins, and returns `Imported { bodies: [(solid entity name, BodyId)], left_open: [solid name], record: RepairRecord, derivative: Option<bytes> }`. `ImportOptions.search_radius_mm` defaults to 1 mm and must match between the two calls.
Rules: every `ask` proposal needs a decision. `accept` needs `tolerance_mm` at least the proposal's `distance_max_mm` and a nonempty `approver`. An automatic proposal accepts only `decline`. An `opening` proposal accepts only `decline`. A declined gap leaves its solid open; it is listed in `left_open` and not built, and `derivative` is absent when nothing was repaired. Ids are `g0`, `g1`, ... in the order of the lowest entity name of each gap; the recipe decision key is the proposal's `question`. `derivative` is canonical text of the repaired recognised data, and `record.derivative.sha256` is its SHA-256. Refusals added in use: `invalid_decision`, `validation_failed`, `not_solid` (an open boundary or a curved gap).
Why: SolidDraft needs the proposal and decision flow to run from the source bytes.
Migration: None for existing callers. The scope of what is repaired is in [the contract](../pieces/08-step-import-repair.md#implemented-repair-scope).
