## 2026-10-31: P5 certified exchange, STEP, display and volume

Pieces: topology, shapes, measure, mesh, step, features, app, CLI, judge interface
Change: an ordinary `source:"recipe"` request whose result has rolling-envelope faces now answers with manifest/4 instead of `numbers.geometric-gap-unproven`. It carries a complete region map with four named exceptions, a raw-valid STEP file and a volume, area and centroid enclosure of the original definition. The certified wrapper accepts recipe/4 with unchanged recipe/3 semantics. `catallax_mesh::mesh_body` displays these bodies from a structured carrier grid whose rows seed the shared edges. `catallax_measure` answers volume, area and centroid through a new `Model::blend_base` record, and `mass_properties` keeps `measure.unsupported-surface`.
Why: the fitted body already built inside the application allowance, but no consumer could use it. Removing the refusal alone would have kept manifest/3's exactness promise on fitted geometry.
Migration: a caller that matched the P5 refusal now sees `format:"catallax-manifest/4"` with `exact:false`, and should read `certificate.regions` and per-region `file_to_definition_bound_mm`. `CertifiedBuilt::result_certificate` still returns the prism record and panics on a junction, so generic code moves to `result_record`, and `junction` gives the fitted record. Every other recipe keeps its manifest and its STEP bytes.
