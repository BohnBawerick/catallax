## 2026-11-11: a refusal keeps the undecided decision it stopped on

Pieces: all
Change: `Refusal` gains a private field holding the `NotExact` a refusal stopped on. `Refusal::from(NotExact)` refuses with the decision's own code and detail, `keeping(decision)` attaches a decision to a refusal that reports its own code, `keeping_undecided(outcome)` does so for a wildcard arm only when the outcome was `NotExact`, `with_code(code)` recodes a refusal without losing its decision, and `undecided()` reads it back. Every site that turned a `NotExact` into a refusal now keeps it, including the wrappers that report a piece code such as `features.precision`, `boolean.classify-ambiguous`, `features.unsupported-curved-limit`, `field.curved-limit-unresolved` and `measure.bounds-not-separated`. Refusal codes, details, `Display` and manifests are unchanged; `Debug` prints the decision only when one is attached.
Why: about 500 call sites dropped the numbers code and residual bound of an undecided decision ([NOT-EXACT-INVENTORY.md](../NOT-EXACT-INVENTORY.md), section 2.4). A tolerance rule needs both, and without them budget exhaustion looked the same as unsupported geometry. This is the first group of M12 in [PLAN.md](../archive/PLAN-2026-11.md).
Migration: build refusals with `Refusal::new`; a struct literal no longer compiles. Turn a `NotExact` into a refusal with `Refusal::from(n)` or `Refusal::new(code, detail).keeping(n)`, never `Refusal::new(n.code, n.detail)`. Recode a refusal with `with_code`, or by assigning `code` or `detail`, rather than building a new one from its parts. Refusal equality now compares the attached decision too.
