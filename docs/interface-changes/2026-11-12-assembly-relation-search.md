## 2026-11-12: field assembly relation searches past contact, on every core

Pieces: field (`catallax_field::assembly`)
Change: `assembly::relation` no longer stops at the first certified common point of the two closed solids. It keeps searching for a point inside both, and refuses `assembly.contact` only when the pair limit runs out with a proven zero gap. Box pairs are taken from the cover in rounds of 32, in lower-bound and creation order, and helper threads evaluate a round ahead of the request's thread, which adopts their recorded charges in order. Each evaluated pair also proposes material points bisected from both box centres toward the other box. An `assembly.pair-budget` refusal now states the enclosure reached, rounded outward to six significant digits, and never publishes it as an answer. `PlacedPart::plan` returns the placed field. This revises the search described in [the M17 first cut](2026-11-11-bounded-assembly-queries.md).
Why: PLAN M17 asks every placed pair to answer clash, clear with a proven smallest gap, or unresolved with a typed reason. The first cut returned `assembly.contact` for coincident and interpenetrating copies of P1, P3 and P6 whose first proposal lay on both boundaries. It ran serially, while the 11 November decision asks every request to use every core with identical answers. Box centres alone converge the upper bound too slowly for curved and turned faces.
Migration: callers that treated `assembly.contact` as cheap must allow for the whole pair limit being spent first. Answers, refusals and operation work are identical at 1, 2, 4 and all threads; a `Decider`'s own statistics exclude work adopted from helper threads, so compare `current_operation_work` instead. The search order changed, so a pair limit that answered under the first cut may need more pairs, or fewer.
