## 2026-11-21: numerical STEP export records its tolerance, and reopening trusts it

Pieces: topology, step, import, cli, app (every piece that writes a numerical STEP file or opens one)
Change: `catallax_step::numerical::build` no longer admits the values it writes. `NumericalStepReport::emitted_evidence` is gone. The report has `rounding: RoundingError` (new public types `RoundingError`, `RoundingErrors`, `RoundingLevers`), and `uncertainty_mm` is now the tolerance the file records: the body's largest entity tolerance plus the rounding error, rounded up to the written digits. The header's `FILE_DESCRIPTION` gains a second string after the stamp, `catallax recorded tolerance;rounding_error_mm=...;recorded_tolerance_mm=...`, so every numerical file's bytes change. The record is apart from the stamp because the stamp holds the body's name and the receiver's, which are a caller's text. The file check name `file.decimal-model-numerical-admission` is replaced by `file.rounding-error-added-to-tolerance`, and `file.decimal-analytic-carriers-and-pcurves-numerical-admission` loses its last word. An export that used to refuse with `numbers.numerical-tolerance-exceeded`, `numerical.tolerance-pair` or a trim refusal because rounding moved the written values now writes the file. New `catallax_step::numerical::audit_written` writes the same bytes and then admits them, as the export did before, and returns `WrittenAudit { file, evidence }`. The CLI manifests replace `numerical.emitted` with `numerical.written` (`recorded_tolerance_mm`, `rounding_error_mm`, `largest_errors`, `levers`). On the reading side, new public module `catallax_import::recorded` with `recorded_tolerance(bytes)`, `RecordedTolerance` and `RecordedField`. The record is read from its own string and nothing is read from the stamp beside it. The scale is the file's own length unit and not the stamp's `scaled_export` note. A file from before this step counts its `source_tolerance_mm` where the stamp holds it once. Also new `catallax_topology::numerical::admit_recorded` and the check names `tolerance::RECORDED_USE` and `tolerance::RECORDED_VERTEX`; new `TolerantSolid::recorded_tolerance_mm()`. `open_step`, `reopen`, `numerical::import_step` and `tolerant::admission::import_step` take a file that records its tolerance with that tolerance and measure nothing.
Also changed, for a file that records nothing: `catallax_topology::numerical::gap::EdgeCopies::curve` is now a `GapCurve` (`Kernel(&Curve)` or `Sampled(&SampledCurve)`), and `GapSurface` has a third variant, `Sampled(&SampledSurface)`. New public types `gap::SampledCurve`, `gap::SampledSurface`, `gap::CurveEvaluator` and `gap::SurfaceEvaluator` let the checker read a carrier with no kernel form through a binary64 evaluator. New `numerical::read_import_use` and `ImportUseReading` are the gap rule for imports on one edge use. The native tolerant admission calls it for every edge use that carries a file u/v curve. `tolerant::admission::NativeTrim` gains `reparametrised: Option<ReparametrisedTrace>`, `TolerantEvidence` gains `import_gaps: Vec<NativeImportGap>`, and both fields are left out of the JSON where they are empty. A use the checker does not read gets an `import-gap-rule-unread` warning. A body whose edge use spends the checker's work cap is refused with `numerical.gap-work-cap`. The tolerant import's STEP export writes a reparametrised copy as a PCURVE named `source trace in the parameter of its 3D curve`.
Why: roadmap item 3.0A step 5, check once (section 4.1 item 5 of the Checkpoint 2 decisions): "Export writes the numbers and adds the rounding error to the tolerance; it does not re-admit the body. Reopening trusts the tolerance recorded at export." See [the check-once note](../milestones/3.0A-check-once.md).
Migration: code that read `emitted_evidence` calls `audit_written` and reads `evidence`; do that in tests and CI, not on a user's export. Code that compared a numerical file's bytes or hash with a stored value regenerates the value. Code that reads the stamp as the header's only description string reads the first of two. Code that relied on an export refusing a body whose rounding breaks its limit reads `uncertainty_mm` and decides for itself. Code that parses a manifest reads `numerical.written` where it read `numerical.emitted`. Code that opens a Catallax numerical file and expects measured evidence finds the recorded check names instead: `trim.edge-surface-recorded-tolerance` and `edge.vertex-recorded-tolerance` on a numerical body, `face.recorded-tolerance-written-uv` and `edge.recorded-tolerance` on a native tolerant one, with every entity at the recorded tolerance. Code that counts edge-surface records counts the recorded name with the others. A test fixture made by editing a Catallax file by hand drops the stamp if it means the file to be measured. Code that builds `gap::EdgeCopies` writes `curve: GapCurve::Kernel(&curve)`, and code that matches on `GapSurface` adds the `Sampled` arm. Code that builds a `NativeTrim` or a `TolerantEvidence` sets the new field. Code that reads a tolerant body's face copies reads `reparametrised` before `source_pcurve`: a use holds one or the other, or a reconstructed trace. An edge tolerance of a tolerant body opened from a file with u/v curves can be larger than before, because the A+ checker reads between the 17 stations.
