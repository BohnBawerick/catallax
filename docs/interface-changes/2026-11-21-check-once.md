## 2026-11-21: numerical STEP export records its tolerance, and reopening trusts it

Pieces: topology, step, import, cli, app (every piece that writes a numerical STEP file or opens one)
Change: `catallax_step::numerical::build` no longer admits the values it writes. `NumericalStepReport::emitted_evidence` is gone. The report has `rounding: RoundingError` (new public types `RoundingError`, `RoundingErrors`, `RoundingLevers`), and `uncertainty_mm` is now the tolerance the file records: the body's largest entity tolerance plus the rounding error, rounded up to the written digits. The stamp in `FILE_DESCRIPTION` gains two fields after the existing ones, `rounding_error_mm` and `recorded_tolerance_mm`, so every numerical file's bytes change. The file check name `file.decimal-model-numerical-admission` is replaced by `file.rounding-error-added-to-tolerance`, and `file.decimal-analytic-carriers-and-pcurves-numerical-admission` loses its last word. An export that used to refuse with `numbers.numerical-tolerance-exceeded`, `numerical.tolerance-pair` or a trim refusal because rounding moved the written values now writes the file. New `catallax_step::numerical::audit_written` writes the same bytes and then admits them, as the export did before, and returns `WrittenAudit { file, evidence }`. The CLI manifests replace `numerical.emitted` with `numerical.written` (`recorded_tolerance_mm`, `rounding_error_mm`, `largest_errors`, `levers`). On the reading side, new public module `catallax_import::recorded` with `recorded_tolerance(bytes)`, `RecordedTolerance` and `RecordedField`; new `catallax_topology::numerical::admit_recorded` and the check names `tolerance::RECORDED_USE` and `tolerance::RECORDED_VERTEX`; new `TolerantSolid::recorded_tolerance_mm()`. `open_step`, `reopen`, `numerical::import_step` and `tolerant::admission::import_step` take a file that records its tolerance with that tolerance and measure nothing.
Why: roadmap item 3.0A step 5, check once (section 4.1 item 5 of the Checkpoint 2 decisions): "Export writes the numbers and adds the rounding error to the tolerance; it does not re-admit the body. Reopening trusts the tolerance recorded at export." See [the check-once note](../milestones/3.0A-check-once.md).
Migration: code that read `emitted_evidence` calls `audit_written` and reads `evidence`; do that in tests and CI, not on a user's export. Code that compared a numerical file's bytes or hash with a stored value regenerates the value. Code that relied on an export refusing a body whose rounding breaks its limit reads `uncertainty_mm` and decides for itself. Code that parses a manifest reads `numerical.written` where it read `numerical.emitted`. Code that opens a Catallax numerical file and expects measured evidence finds the recorded check names instead: `trim.edge-surface-recorded-tolerance` and `edge.vertex-recorded-tolerance` on a numerical body, `face.recorded-tolerance-written-uv` and `edge.recorded-tolerance` on a native tolerant one, with every entity at the recorded tolerance. Code that counts edge-surface records counts the recorded name with the others. A test fixture made by editing a Catallax file by hand drops the stamp if it means the file to be measured.
