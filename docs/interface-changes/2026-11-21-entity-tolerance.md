## 2026-11-21: vertex, edge and face gain an optional tolerance

Pieces: 3, and every piece that builds a `Vertex`, `Edge` or `Face` (4 to 10, the app and the CLI); the body handover format
Change: `catallax_topology::Vertex`, `Edge` and `Face` gain `tolerance: Option<Tolerance>`. `None` is exact. `Tolerance` is a new type: a length in millimetres, always greater than zero; `Tolerance::new` refuses others with `topology.tolerance-not-positive`. `Model::check` gains the fault `topology.tolerance-order` (vertex >= edge >= face, with exact as zero), and asks for a recorded `Incident` fact only where both entities of a pair are exact. The body handover format moves to version 3, which stores the three tolerances; versions 1 and 2 still read, with every entity exact. `NumericalBody::exact_topology_faults` is replaced by `NumericalBody::topology_faults`, which is `Model::check` on the body's model and is empty for an admitted body, and `NumericalBody::stored_tolerance` reads a vertex's or an edge's tolerance from that model by key.
Why: roadmap item 3.0B, one model ([Checkpoint 2 decisions, section 4.5](../checkpoints/checkpoint-2-decisions.md#45-item-30b-one-model-and-the-predictor), Q12): one topology type in which exact and tolerant entities coexist, and one checker. Method and limits are in [the milestone note](../milestones/3.0B-one-model.md).
Migration: add `tolerance: None` to a literal that makes a new exact entity. Where a literal copies an existing entity, on the same point, curve or surface, carry the source's tolerance (`..source.clone()` or `tolerance: source.tolerance.clone()`): writing `None` there calls a tolerant entity exact. Replace `exact_topology_faults()` with `topology_faults()`; a test that asserted it non-empty to show a numerical body is not exact now asserts that `stored_tolerance` is `Some` for its vertices and edges. A reader of handover bytes must accept version 3.
