## 2026-11-21: the gap rule for imports

Pieces: topology, import (every piece that admits an imported numerical body)
Change: `numerical::admit_import` now applies decision Q9 before rule T3. An imported edge use whose same-parameter gap is more than 1.1 times its geometric gap gets a new face copy in the parameter of its 3D curve, a retained u/v curve in `NumericalBody::native_trims()`, and stores the tolerance of that copy. New `NumericalBody::import_gaps()` returns one `ImportGapRow` per use that was read geometrically, with an `ImportGapOutcome` (`Geometric`, `Reparametrised`, `NotLowered`, `NotAdmitted`); the rows are not stored with the body. New in `catallax_topology::numerical::gap`: `measure_geometric` and `GeometricMeasure` (the geometric gap of an edge use, both ways) and `refit::reparametrise` (the change of parameter). Both take the `Limits` the edge use has left of its one work allowance. `reparametrise` returns a `refit::Fit`, the new copy where there is one and the work taken. New `refit::refit_within` is the refit from the 3D curve under such `Limits`, and `refit::Refit` has a new `reading` field, the checker's reading of the copy. `ImportGapRow` has a `work` field. `admit_import` can now refuse with `numerical.gap-work-cap` for a use whose same-parameter reading, geometric reading, change of parameter and rule T3 refit together spend that allowance. An import whose stored tolerances are all at rule T1's least floor is admitted as before and charges two more work units per edge use. Own builds, continuations and exports are unchanged.
Why: roadmap item 3.0A, decision Q9 and section 4.2 step 2 of the Checkpoint 2 decisions. See [the note on the gap rule for imports](../milestones/3.0A-import-gap-rule.md).
Migration: none for a caller that reads the body it gets back. A caller that compared the retained u/v curves of an admitted import with the ones it passed in, or counted a face's check names, must expect a new curve on a reparametrised use, and the sampled check names of a face that has one. A caller that expected `numbers.numerical-tolerance-exceeded` from `admit_import` for copies that differ only in speed now gets the body.
