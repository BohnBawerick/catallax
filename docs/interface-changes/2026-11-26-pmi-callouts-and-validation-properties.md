## 2026-11-26: graphic surface texture callouts and PMI validation properties

Pieces: 7; SolidDraft adapter
Change: `write_step_with_pmi` adds entities to a file with manufacturing information. Each surface texture also gets a graphic callout: a `DRAUGHTING_CALLOUT` of polylines in one front-facing `ANNOTATION_PLANE` and `DRAUGHTING_MODEL`, linked by a `DRAUGHTING_MODEL_ITEM_ASSOCIATION` to a `SHAPE_ASPECT` of its own on the texture's faces. The file also carries the CAx-IF PMI validation properties that AP242 edition 1 allows. The part gets counts of semantic elements by type and of annotations. Each datum and distance gets its equivalent Unicode string. Each callout gets its string, polyline length and centre. No Rust signature changes, and a file without PMI items keeps its bytes.
Why: Checkpoint 3 build order item 1 and research row 27. OpenCASCADE has no reader for the semantic surface texture but reads the callout as a presentation on the textured faces, so all fourteen P1 bracket items reach it. The validation properties let a receiver check that nothing was lost.
Migration: a reader that counts presentation items or `SHAPE_ASPECT` entities in a PMI file sees one more of each per surface texture. SolidDraft's OpenCASCADE expectation for the P1 bracket gains one `DimensionPresentation` on the bore when it moves its Catallax pin past this change. `catallax_import::read_step_pmi` reads the same items as before.
