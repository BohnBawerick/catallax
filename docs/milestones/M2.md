# M2: Catallax 0.2.0 release preparation

## Release freeze, 14 November 2026

The owner selected Catallax 0.2.0 and SolidDraft 0.5.0 for the joint release.
The frozen kernel source is `ad826a1dc5aaa1abf7500e5ca484ff82d9aae4fb`.
`release/0.2.0` starts at that commit; the preparation change updates only the
workspace version, Cargo-generated lockfile and this note. Development continues
on `main`. This note records the selected scope and the remaining release gates;
it does not claim new application measurements or completed M12 acceptance.

The source's [main push check](https://github.com/BohnBawerick/catallax/actions/runs/43508935478)
is green with documentation selection. It is not the full-suite release-branch
push check required on the final release commit.

### P0, target parts and regressions

Keep the historical P0 and target-part counts below attached to their measured
sources. The [M12 exit run](M12.md) records 460 answers and seventeen refusals
across the unchanged 477 saved requests, with 4,994,607,939 charged units and
strict agreement at 1/2/4 workers. Its wider rebuild corpus records twenty
answers and three refusals across 23 requests, also strictly equal at 1/2/4.
Those are pre-freeze preservation measurements, not a release-baseline replay.

All P1-P5 five-stage no-growth chains build within 20M in that exit run. The
M10 table records additional export work of 44,378, 44,378, 43,019 and 1,281
units on M10-001, M10-002, M10-003 and M10-007 respectively, with the same
numbered refusals. M12 also retains definition-only fitted-area coverage,
incomplete independent P5 checks and the reported stage-accounting discrepancy.
No work allowance, tolerance or accepted-answer record changes for this cut.

A fresh target scoreboard, including refusal, edit and STEP read-back results,
remains a required evidence-workflow output on the final release commit. Neither
historical scores nor passing refusal regressions establish a completed target.
Timing requirements moved to M26 in the 11 November plan decision.

### Qualification and publication gates

Use v0.1.5 as the previous-release baseline. After the preparation change lands
on `release/0.2.0`, record the final commit and require its green full-suite
`check.yml` push run on that branch. Replay all 477 original requests on the
work PC, baseline at one worker and the same candidate binary freshly at one,
two and four workers. Run the separate 23-case rebuild corpus in that session.
Every baseline difference needs an existing exact approval in
`tools/release/replay-upgrades.json` or `tools/release/replay-corrections.json`;
unlisted changes stop the release for an owner decision.

Generate the public aggregate with `tools/release/release.py`, run the evidence
workflow and the non-publishing package dry run at the exact release commit,
and inspect platform smoke checks, SBOM, generated notes, checksums and
attestations as required by the [release checklist](../RELEASING.md#release-checklist).
Record those run links and the replay summary in the release review. These
gates remain pending at preparation time. No release tag is authorized by this
note. The owner gives the final go before `v0.2.0` is published.

Sponsor delivery of the milestone text is not recorded by this preparation.
The M3 must-show list at the end of this note remains the next milestone's scope.
