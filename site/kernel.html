How the kernel answers.

A geometry kernel is the part of a CAD program that does the geometry: it builds solids, cuts them, rounds their edges and answers questions about them. This page explains how Catallax does that, from first principles. Each idea comes in plain words, then a worked example, then the maths, then the few lines of Rust that do it.

Exact numbers

Most software stores a number like 0.1 as the nearest binary fraction it can hold, which is slightly wrong. The errors are tiny, but a kernel keeps asking yes-or-no questions: is this point on the face, do these two edges touch? A tiny error can flip the answer, and a flipped answer can break a solid.

Catallax keeps the numbers written in a part exactly. The text "1.1" becomes the fraction 11/10, not a binary approximation. Square roots stay exact too. Only a few constants, such as π, can never be written down exactly; those are held between two exact numbers that can be squeezed together as far as a question needs.

Worked example

Ask a spreadsheet for 0.1 + 0.2 − 0.3 and the usual answer is 0.0000000000000000555, not zero. Ask Catallax and the answer is exactly zero, with a proof that it is zero.

The number √2 is stored as “the root of x² − 2 that lies between 1 and 2”. That description is exact, and the kernel can compare it with any other number without rounding.

The maths

110+210−310=0
2=the x with x2−2=0 and 1<x<2

Every exact number in the kernel is a fraction of whole numbers of any size, or a root of a polynomial with whole-number coefficients, pinned down by an interval that holds only that root. π is not such a number, so it is only ever enclosed: 3.14159<π<3.14160, and tighter when needed.

In Rust

This is the worked example as a test in the repository. It builds 0.1 + 0.2 − 0.3 from exact numbers, asks for its sign, and checks that the answer is “proven zero, by exact arithmetic”.

Four kinds of answer

Every question that changes what the kernel builds comes down to the sign of a number: positive, negative or zero. Is the point above the plane? Do the two radii match? Catallax gives every such question one of four labelled answers, and a proven answer is never wrong.

It works in a fixed order. First a cheap estimate with error bars; if the bars do not straddle zero, the sign is settled. If they do, more precision. Then an exact method. If the work allowance runs out before that, it stops and says how far it got. It never decides that a very small number is zero just because it is small.

Worked example

Is √2 greater than 1.41421356? Yes, proven. Is 0.1 + 0.2 − 0.3 zero? Yes, proven zero. A long calculation that runs out of allowance might return “not exact: the value lies between −0.000001 and 0.000001”, which is still a true statement. A question that has no answer, such as one about a profile the field cannot read yet, is refused by name.

The maths

AnswerWhat is proven about the quantity x
Provenx>0 or x<0, certified
ProvenCoincidentx=0 exactly, with a recorded proof
NotExact−b≤x≤b for a stated bound b
RefusedThe question cannot be answered; the reason is named

In Rust

An enum is a list of the only shapes an answer can take. Code that receives an Outcome has to handle all four.

Signed distance

The second kernel describes a solid differently. Instead of faces and edges, it uses a function that takes any point in space and returns a number: how far the point is from the surface, negative inside and positive outside. Zero means the point is on the surface. This is a signed distance field.

Worked example

A sphere of radius 5 mm, centred at the origin. The point (3, 4, 0) is √(9 + 16) = 5 mm from the centre, so its value is 5 − 5 = 0: it is on the surface. The point (0, 0, 8) gives 8 − 5 = 3: outside, 3 mm away. The centre gives 0 − 5 = −5: inside, 5 mm deep.

A block 20 × 20 × 10 mm with one corner at the origin. The point (23, 24, 10) lies beyond the corner edge at (20, 20, 10). Its value is √(3² + 4²) = 5 mm, the true straight-line distance to that edge, not 4 mm, which is what the nearest single face would suggest.

The maths

For a point p=(x,y,z) and a sphere of radius r at the origin:

f(p)=x2+y2+z2−r

For a block of size (a1,a2,a3) with a corner at the origin, first measure how far the point is past each pair of opposite faces, then combine:

qi=max(−pi,pi−ai)f(p)=∑imax(qi,0)2+min(maxiqi,0)

Combining solids is then simple. For solids A and B with values fA and fB:

unionmin(fA,fB)intersectionmax(fA,fB)A minus Bmax(fA,−fB)

A point 2 mm inside A and 1 mm inside B gives max(−2, 1) = 1 for A minus B: outside the result, because it sits in the hole. After a combination the value is no longer the exact distance, only a proven lower bound on it, |f(p)|≤distance to the surface. The field labels which kind of value it returns.

In Rust

The first excerpt is the two formulas above, term for term: a holds the block's size or the sphere's radius. The second is the min and max rule for combining solids.

Fillets: the rolling ball

A fillet rounds a sharp edge. Catallax defines it the way a machinist would picture it: roll a ball of radius r along the edge so that it always touches both faces. The ball's surface between the two contact lines is the fillet. Material outside it is removed on a convex edge and added on a concave one.

Worked example

The gallery's box-single case is a 20 × 20 × 10 mm block with one 20 mm top edge rounded at r = 1 mm. Seen end-on, the fillet cuts a square corner of side 1 mm and puts back a quarter of a circle of radius 1 mm. The area removed is 1 − π/4 = 0.2146 mm², along 20 mm of edge.

Volume = 4000 − 20 × 0.2146… = 3995.708 mm³. The repository's fillet tests use this closed form to check exported solids, and the compare page lists closed-form volume checks for harder cases.

The maths

The ball's centre c stays at distance r from both face surfaces SA and SB:

dist(c,SA)=dist(c,SB)=r

Where two flat faces meet at an angle α, each contact line sits a distance s from the edge, and the fillet removes an area A from every cross-section:

s=rcotα2A=r2(cotα2−π−α2)

At a right angle, α=π2, this gives s=r and A=r2(1−π4), the worked example. A variable-radius fillet changes the radius steadily along the edge, from rstart to rend, where u runs from 0 to 1 along it:

r(u)=(1−u)rstart+urend

The full definition, including where three faces meet, is in the recipe reference.

Names that survive edits

Many CAD programs refer to an edge by its position in a list: edge 7. Change a dimension and the list can reorder, so the fillet lands on the wrong edge. Catallax names every face by the operation that made it, and every edge by the two faces it lies between.

Worked example

In box-single, the rounded edge is “between the end face of block b and its x_max side”. Change the block from 20 mm to 30 mm wide and that sentence still points at the same edge. No name holds a dimension, so changing a parameter never changes a name.

The maths

A face's name is its origin: the step that made it and the role it plays in that step. An edge's name is the pair of its two faces' origins, written in a fixed order so that the pair has one spelling:

edge={origin(A),origin(B)}

In the recipe

This is not Rust but the recipe file itself: the fillet step names its edge as the pair of two origins, and gives the radius as the exact text "1".

Checking two kernels

The B-rep kernel and the field kernel build the same recipe independently. Comparing them catches mistakes that either could make alone. The comparison runs both ways: from the B-rep to the field, and from the field to the B-rep, because a shape can be missing a piece that a one-way check would never visit.

Worked example

A display-mesh vertex of the B-rep is known to lie within 0.002 mm of the exact surface. The field proves the vertex is between 0.0005 and 0.003 mm from its surface. So the two surfaces are at most 0.003 + 0.002 = 0.005 mm apart there, inside the default display accuracy of 0.01 mm: settled. Had the field proved at least 0.02 mm, the gap would be at least 0.018 mm: a proven disagreement.

The maths

The usual measure of how far apart two surfaces X and Y are is the Hausdorff distance: the furthest any point of either is from the other.

dH(X,Y)=max{supx∈Xd(x,Y),supy∈Yd(y,X)}

The forward pass samples the first term, the reverse pass the second. Because they sample, the result is a bound at the sampled points, not a certificate for the whole part. At each sample, with mesh error e and the field's proven distance between l and u:

gap≥max(0,l−e)gap≤u+e

A lower bound above the accuracy proves a disagreement. An upper bound within it settles the sample. Anything else stays unresolved.

Refusals

When the kernel cannot build something, it stops, publishes nothing partial, and says why with a stable code of the form piece.reason. A refusal is reported as a refusal, never as a finished part.

Worked examples

field.ellipse-profile: the field kernel does not read ellipse profiles yet. fillet.unsupported-end: a fillet strip ends in a way the builder does not trim yet. numbers.operation-budget: the request used up its work allowance.

The work allowance is counted from the sizes of the numbers involved, not from the clock, so the same request runs out at the same point on every machine.

In Rust

Err means “this did not work”. The refusal carries the stable code and a sentence for people.

Same answer everywhere

The rule the code is held to: the same recipe and question give the same outcome, topology and proven bounds on every machine and at every thread count. An exported STEP file has the same bytes every time, and a recipe file has one spelling, so equal parts have equal files.

One older command still stops at a 50-second wall-clock deadline, which can make the same question refuse on a busy machine. The verification path counts work instead.

Reading the Rust

  • let x = … gives a value a name.
  • real("0.1") is the exact number 0.1.
  • a.max(&b) is max(a, b); .sqrt(), .square(), .add and .sub are what they say.
  • enum lists every form a value can take; match handles each one.
  • assert_eq!(a, b) fails the test unless a equals b.
  • Lines starting /// are documentation for people.
