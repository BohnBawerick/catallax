catallax Checkpoint 1 Testing Code

How Catallax is tested.

A change merges only after its checks pass. A release must reproduce every answer the last release gave. At each checkpoint, Catallax is measured against OpenCASCADE and SMLib on the same parts and on 3,000 real STEP files.

On every change

Each pull request runs the checks its change can affect, and a kernel change runs all of them. The full set also runs every night on the main branch, even when nothing in the kernel changed.

Saved answers, replayed

Catallax keeps 477 earlier requests with a fingerprint of each accepted answer: 85 unions, 89 subtractions, 86 intersections and 217 mixed requests. Every answer must come back with the same record and the same output bytes. A difference fails the check unless someone reviews it and lists it, for example a request that used to be refused and now gets a correct answer.

A release replays all 477 against the previous release, together with 23 rebuilt parts. The previous release runs on one worker. The new build runs fresh on one, two and four workers, and those three runs must agree exactly, with no exceptions.

Before the 0.3.0 freeze, a fresh replay compared release 0.2.0 with the frozen commit: all 477 requests and all 23 rebuilt parts came out equal, records and output bytes. The release repeats the replay at one, two and four workers on the final commit before it is published.

STEP files read back in OpenCASCADE

A STEP file is only useful if other software can open it. The read-back tests load Catallax's actual output bytes into OpenCASCADE, the kernel behind FreeCAD and CadQuery, and check that the solid is valid and has the right faces. Several read the file raw: no ShapeFix repair, no sewing, no tolerance fixing, and nothing rewritten first. The checks on approximate STEP also make a later cut on the file in OpenCASCADE, to show it can be worked on.

At Checkpoint 1, the test parts P1 to P5 were built, edited, saved and reopened in SolidDraft, and every STEP export opened as valid in OpenCASCADE with repair turned off.

Measured at each checkpoint

Two measures compare Catallax with the reference kernels. Both run once per checkpoint, each as one command, and the Checkpoint 1 page has the results.

  • Edit-chain scoreboard. 23 target parts, each built and then rebuilt after one change, in Catallax, OpenCASCADE and SMLib. All three kernels are judged by one definition of done: both versions build, both STEP exports open in OpenCASCADE as valid closed solids, and no independent check finds a wrong value. At Checkpoint 1 Catallax finished 10 of 13 test parts and 6 of 10 real parts; OpenCASCADE 12 and 7; SMLib 8 and 6.
  • STEP census. 3,000 models from the public ABC collection, picked with a fixed seed. A file counts only when every body imports, exports again, and passes OpenCASCADE's validity check. At Checkpoint 1, 374 files passed (12.47%), checked after the OpenCASCADE builder, which may heal pcurves. OpenCASCADE opens 2,701 (90.03%) after its own default repair, so the two figures compare how many files open, not accuracy at one tolerance.
  • Freeform cut requests. 14 recorded requests that cut or join lofted solids. 11 now write a checked approximate STEP file; three are still refused.

What the tests do not prove

Passing tests show that the cases tested give the recorded answers. They do not prove every part correct. Point checks sample a part; they do not cover all of it. A refusal is reported as a refusal and is never counted as a pass.

Counts are from the main branch at commit 44bf90eb, the release guide and the Checkpoint 1 report.
